# 티켓레이더(가칭) 디자인 토큰

- 작성일: 2026-10-31
- 근거: `docs/suno-ui-reference.md`(Suno iOS UI 관찰 기록). 모양·색은 Suno를 따르고, 문구·정보·버튼 개수는 `docs/screen-spec-ticket-radar.md`를 따른다.

### 심각도 3단계 (라벨 = 작은 아이콘 + 색 글자, 바탕 없음)

Suno의 "♥ Most Popular / ★ Best Value"처럼 **바탕색 없이 색 글자 + 아이콘**으로 표시한다. 연한 바탕 + 진한 글자의 틴트 배지는 쓰지 않는다(AI 템플릿 인상). 카드 `tr-card` 위에서의 대비를 적었다.

| 라벨 | 아이콘 | 글자 토큰 | 값 | 대비 |
|---|---|---|---|---|
| 정보 | `info` | `tr-sev-info-fg` | `#7CC4FF` | 9.6:1 |
| 주의 | `warning` | `tr-sev-warn-fg` | `#FFC53D` | 11.0:1 |
| 확인 필요 | `search` | `tr-sev-check-fg` | `#FF8A3D` | 7.3:1 |

`tr-sev-*-bg`(짙은 바탕 3색)는 등록만 되어 있고 현재 쓰지 않는다. PC 화면처럼 바탕이 필요해질 때를 위한 예비값.

규칙: "확인 필요"는 빨강 계열을 쓰지 않는다(경고·판정 인상 금지). 색만으로 구분하지 않고 글자 라벨을 항상 같이 쓴다.

## 1-1. 라이트 모드 값 (2026-11-01 추가)

셰이더 메모: pen의 셰이더 uniform에는 `"$tr-…"` 변수를 넣을 수 있어서, 버튼 질감·배경 물결·점선 색이 모드에 따라 자동으로 바뀐다. 배경 셰이더에는 흰 바탕에서 생기던 동심원 줄무늬(밴딩)를 없애는 디더링(픽셀마다 ±1/255 노이즈)을 넣었다. 또 PNG 내보내기 렌더러가 소수 정밀도가 낮게(mediump) 돌 때 노이즈 좌표가 커지면 계단처럼 끊겨 보여서, 셰이더 안의 좌표·상수를 모두 작게(좌표 20 이하, 해시 곱 43.76) 유지한다. 새 셰이더를 쓸 때도 같은 규칙을 따를 것.

**유리 카드(2026-11-01)**: 카드 계열 부품(입력 카드, 결과 항목 카드, 섹션 카드, 옵션 행, 대화상자, 진행 알약, 스켈레톤 카드)에 `effect: {type: "background_blur", radius: 24}`를 주어 뒤의 물결이 흐릿하게 비친다. 카드 바탕은 반투명(`tr-card`)이어야 효과가 보인다. 코드에서는 `backdrop-filter: blur(24px)` + 반투명 배경. 배경 물결이 거의 평평하면 블러가 티 나지 않으므로 물결 세기(`tr-glow-strength`)는 다크 0.14(거의 안 띄게) / 라이트 0.26(눈에 보이게)으로 둔다.

## 5. 지키는 규칙

1. 화면마다 주인공 버튼(질감 알약)은 하나. 나머지는 회색·흰 알약.
2. 입력칸은 화면당 3개 이하. 본문 글자는 16px 이상, 라벨·메타는 13px 이상(12px는 쓰지 않는다).
2-1. 가독성: 읽혀야 하는 글자는 바탕과 대비 4.5:1 이상(`tr-text`, `tr-text-sub`, `tr-text-placeholder`만). 20자 넘는 문장은 줄간격 1.5. 화면 아래 여백은 32(홈 바 영역).
3. 배지는 색 + 글자 라벨. "확인 필요"에 빨강 금지. 분홍은 링크·선택·로딩에만.
4. 금지 단어(암표·암표상·불법·사기·상습·범죄)는 어떤 글자에도 쓰지 않는다.
5. 명세표의 "절대 넣지 않는 것"(로그인, 검색, 피드, 공유, 점수, 광고)은 부품이 있어도 넣지 않는다.
6. 오류는 **원인별로 한 장씩** 그린다. ① 이미지 오류: 파일 줄 바로 아래 빨간 글 + "다른 이미지 올리기" 회색 알약, 글이 유효하면 주요 버튼은 그대로 활성. ① 연결 실패: 입력은 그대로 두고 카드 아래 가운데 안내 한 줄, 재시도는 **주요 버튼 "다시 시도" 하나**로(같은 일을 하는 버튼을 둘 두지 않는다).
7. 로딩 중에는 주요 버튼을 "읽는 중…" 비활성으로 바꾸고, + 원·캡처 칩·? 원·휴지통도 **투명도 40%**로 함께 비활성 표시한다(읽는 동안 수정·삭제 불가).
8. 화면 ②(2026-11-01): 세션 카드는 안쪽 14 · 요소 간격 12, 옵션 행 52, 칩 32로 맞춰야 390×844 한 화면에 카드 3개 + 추가 항목 행 + 주요 버튼이 스크롤 없이 들어간다(남는 높이 약 14px). 값이 틀린 칸은 근거 칩을 숨기고 그 자리에 빨간 오류 줄을 둔다. 비교 실패(오류 B)는 맨 위 안내 줄을 빼고 주요 버튼 바로 위에 오류색 한 줄 + 주요 버튼 "다시 시도". "판매글 다시 보기"는 상단 바 오른쪽 알약 "판매글 ▾"로, "처음부터 다시"는 휴지통 원으로 둔다.
9. 화면 ③(2026-11-01): 모바일은 카드가 화면보다 길어 **스크롤**을 전제로 그렸다(390×844에 요약 + 카드 1장 + 2장 일부가 보이고, 아래 고정 띠 `tr-bg-veil` 68px에 고정 문구). 카드마다 이름 + 색 라벨, 판매글 구절 20/600, 공식 안내 블록(`tr-inner`), 쉬운 말 설명, "예매처에 재확인" 회색 알약 + "공식 안내 원문 보기" 분홍/파랑 링크 알약. 목록 끝에 흰 알약 "다른 판매글 확인하기" + 회색 알약 "공식 신고센터". 빈 상태는 "확인이 필요한 부분을 찾지 못했어요"("안전"이라는 말 금지) + 흰 알약 원문 링크.
