# 티켓레이더(가칭) — AI 작업 지시용 기획 요약

이 문서는 팀이 확정한 기획이다. 사람용 기획서(`docs/prd-ticket-radar.md`)에서 AI가 작업할 때 필요한 확정 사항만 추렸다.
기준일 2026-10-27. 2026 AID AI-Thon 해커톤 출품작. 팀 월32(4명), 최종 책임자 팀장.

## 0. 이 문서를 받은 AI가 지킬 것

1. 여기 적힌 범위 밖의 기능은 만들지 않는다. "있으면 좋을 것 같은" 기능을 제안하더라도 구현하지 않는다.
2. 이 문서가 비어 있거나 둘로 읽히는 부분은 추측해서 채우지 말고 질문한다.
3. 판단(대조·판정)은 코드로 짠다. AI 호출은 "추출"과 "쉬운 말 설명"에만 쓴다.
4. 화면·설명·코드 주석 어디에도 "암표", "불법", "사기", "암표상"처럼 법적 판단을 단정하는 단어를 쓰지 않는다. 결과의 이름은 항상 **"확인이 필요한 부분"** 이다.
5. 실제 사람의 판매글·연락처·계정·사진을 테스트 데이터로 쓰지 않는다. 가상 글과 `010-0000-xxxx` 대역의 가상 번호만 쓴다.

## 1. 한 줄 정의

중고 공연 티켓을 사려는 팬이 판매글을 붙여넣거나 캡처를 올리면, AI가 가격·좌석·전달 방식 등 핵심 정보를 뽑고, 서비스가 그 공연의 공식 정가·입장·양도 규정과 대조해 "확인이 필요한 부분"을 판매글 원문 구절과 공식 출처와 함께 보여주는 **반응형 웹**. 티켓 진위나 사기·불법 여부는 확정하지 않는다. 최종 판단은 사용자가 한다.

## 2. 사용자

| 사용자 | 하는 일 |
|---|---|
| 팬 (로그인 없음) | 공연 선택 → 판매글 입력 → AI 추출 결과 확인·수정 → 확인사항 결과 보기 |
| 관리자 (팀원) | 파일로 넣어 둔 공연 1건의 정가표·규정을 화면에서 재확인·수정 |

## 3. 핵심 흐름 (Must)

| 순서 | 화면 | 사용자가 하는 일 | 다음으로 가는 조건 |
|---|---|---|---|
| 0 | 홈 (첫 화면) | 서비스 한 줄 설명(진위·위법 여부는 판단하지 않음), "이렇게 확인해요" 3단계, 확인 가능한 공연 1건(이름·일시·장소·공식 안내 링크)을 보고 "판매글 확인하기"를 누른다. 공연 정보가 없으면 안내 + 버튼 비활성 | 버튼 누름 |
| 1 | 판매글 입력 | 공연을 고르고 판매글 텍스트를 붙여넣거나 캡처 이미지를 올린다 | 공연 선택됨 + 글 또는 이미지 중 하나 이상 |
| 2 | 추출 결과 확인 | AI가 뽑은 가격(1장당)·좌석·수량·전달 방식·선입금 여부를 보고 틀린 값을 고친다. AI가 실패했으면 빈 칸에 직접 쓴다 | 가격 또는 전달 방식 중 하나 이상 입력됨 |
| 3 | 확인사항 결과 | 항목마다 "판매글 원문 구절 ↔ 공식 안내 문장 ↔ 출처 URL·확인 날짜"를 나란히 본다. 확인사항이 없으면 "확인이 필요한 부분을 찾지 못했어요. 거래 전 예매처 규정은 꼭 확인하세요"를 본다 (안전하다고 말하지 않음) | 끝 |
| 관리자 | 규정 재확인 | 공연 1건의 정가표(등급별 가격)와 규정 문장을 표로 보고 고친다 | 끝 |

- 첫 화면은 홈이고, 로그인·스플래시 없이 버튼 한 번으로 입력 화면에 간다. 홈에 피드·검색·공유·점수·광고를 넣지 않는다.
- 화면마다 입력칸은 3개 이하를 목표로 한다. 버튼 글씨는 "확인"·"제출"이 아니라 결과를 적는다 (예: "이 판매글 확인하기").
- 모든 화면은 빈 상태 / 로딩 / 오류 / 정상 네 가지 상태를 가진다.
- 모든 결과 화면 하단에 고정 문구: **"이 결과는 참고용이며 최종 판단은 사용자가 합니다."**

## 4. AI와 코드의 역할 분리

| 일 | 담당 | 이유 |
|---|---|---|
| 비정형 판매글(텍스트·캡처)에서 가격·좌석·수량·전달 방식·선입금 여부·원문 구절 뽑기 | AI (구조화된 JSON 출력) | 표현이 다양해 규칙으로 못 잡음 |
| 추출값을 공식 정가·규정과 대조해 "확인이 필요한 부분" 만들기 | 코드 (규칙) | 같은 입력이면 같은 결과, 테스트 가능, 이유 설명 가능 |
| 확인사항을 쉬운 말 1~2문장으로 설명 | AI (선택). 실패하면 템플릿 문장 | 문장만 만들고 판정은 바꾸지 못함 |
| AI 호출 | 서버에서만. API 키는 환경 변수. 클라이언트에 키를 두지 않음 | |
| AI 실패(오류·시간 초과·거부·형식 불일치) | 오류가 아니라 "직접 입력" 안내 + 빈 폼. 서비스는 AI 없이도 끝까지 동작 | 수용 기준 3 |

## 5. 범위

### Must (해커톤 발표까지)
0. 홈 화면 (서비스 설명 + 공연 1건 안내 + "판매글 확인하기")
1. 공연 1건 선택
2. 판매글 텍스트 입력
3. 판매글 캡처 이미지 입력 (일정이 밀리면 가장 먼저 빼는 후보)
4. AI 추출 (가격·좌석·수량·전달 방식·선입금 여부·근거 구절)
5. 추출 결과 확인·수정 폼
6. 공식 정가·입장·양도 규정과 대조 (코드)
7. 확인사항을 원문 구절 + 공식 문장 + 출처 URL + 확인 날짜와 함께 표시
8. AI 실패 시 직접 입력으로 끝까지 진행
9. 관리자가 공식 정가·규정을 재확인·수정하는 화면

### Should (시간이 남으면, Must가 끝나기 전에는 손대지 않음)
1. 제보가 쌓이면 같은 판매자 또는 같은 연락처로 반복 올린 글 찾아 보여주기
2. 제보를 원하는 팬에게 관련 근거를 한 장으로 정리 + 공식 신고 경로 안내

### Won't (만들지 않는다. 요청받아도 만들지 않고 이 목록을 알려 준다)
1. 티켓 진위·사기·불법 여부 자동 확정
2. 판매자 신원(이름·아이디·연락처) 공개
3. 신고 대행(서비스가 대신 제출)
4. 외부 사이트(중고 거래 앱 등)에서 판매글 자동 수집
5. 공연 여러 건, 주최 측 공연 등록 화면
6. 결제·거래 중개, 티켓 양도 기능
7. 결제·구독·광고 (수익 모델)
8. 공식 공지 자동 수집 (데이터는 사람이 손으로 넣는다)
9. 회원가입·로그인
10. 실제 사람의 판매글·연락처·계정을 데이터로 사용
11. 시작 화면(스플래시) — 디자인 파일에 있어도 구현하지 않는다

## 6. 확정된 기술·운영 결정

| 결정 | 내용 |
|---|---|
| 플랫폼 | 웹. 반응형 화면 **한 벌** (PC·모바일 브라우저 모두). PC용·모바일용을 따로 만들지 않음 |
| 입력 | 텍스트 붙여넣기 + 캡처 이미지 업로드 |
| 공식 정가·규정 데이터 | 팀이 공연 1건의 공식 공지를 손으로 옮겨 적은 **파일** (항목마다 출처 URL과 확인 날짜 포함) + 관리자 재확인 화면. 자동 수집 없음 |
| 로그인 | 없음 |
| AI 실패 처리 | 빈 입력칸을 열어 사용자가 직접 입력 |
| 저장 | 서버 안 파일 하나 또는 가벼운 DB 1개. 외부 클라우드 DB 없음 |
| 데이터 | 테스트·시연 글은 전부 팀이 쓴 가상 글. 연락처는 `010-0000-xxxx` 대역만 |

## 7. 문구 규칙

- 결과 명칭: "확인이 필요한 부분". "위험", "의심 매물", "암표" 같은 단정 표현 금지.
- 금지 단어 (화면·템플릿·AI 설명·주석 전부): 암표, 암표상, 불법, 사기, 상습, 범죄. 공식 기관 이름에 들어 있는 경우만 예외.
- 확인사항이 0건일 때도 "안전합니다"라고 쓰지 않는다. "확인이 필요한 부분을 찾지 못했어요. 거래 전 예매처 규정은 꼭 확인하세요."
- 모든 확인사항 카드에 "예매처에 재확인하세요" 안내.
- 고정 문구: "이 결과는 참고용이며 최종 판단은 사용자가 합니다."

## 8. 수용 기준 (이 셋이 통과해야 Must 완료)

| 번호 | 기준 | 확인 방법 |
|---|---|---|
| 1 | 팀이 쓴 가상 판매글 10건(캡처 글 2건 이상 포함) 중 8건 이상에서, 미리 적어 둔 기대 확인사항과 같은 결과 | 검증표(글 ↔ 기대 결과 ↔ 실제 결과) |
| 2 | 정가 이하로 1장만 파는 정상 양도 글 2건에서 확인사항 0건 | 시연에서 직접 입력 |
| 3 | AI 키를 뺀 상태에서 입력 → 직접 입력 → 대조 → 표시가 끝까지 1회 완주 | AI 끄고 실행 |

## 9. 완료의 정의 (각 기능마다)

1. 담당자 컴퓨터가 아니라 시연용 환경에서 동작한다.
2. 정상 글 / AI 실패 / 빈 입력 / 공식 규정에 없는 좌석 등급, 네 경우를 처리한다.
3. 담당자가 아닌 다른 팀원이 직접 써 보고 승인한다.
4. 생성형 AI가 만든 코드·자료는 담당자가 직접 읽고 고친 뒤에만 반영한다.

## 11. 아직 정해지지 않은 것 (AI가 정하지 말 것)

- **대상 공연 1건.** 정해질 때까지 공연 이름·정가표·규정은 `{{EVENT_NAME}}`, `{{PRICE_TABLE}}`, `{{RULES}}` 같은 자리 표시자로 두고, 가상 공연 데이터를 만들어 써야 한다면 "가상"이라고 파일과 화면에 표시한다.
- 구체적 기술 스택(프레임워크·DB 종류·배포 위치)은 6주차 아키텍처 문서에서 정한다. 이 문서는 "반응형 웹 한 벌, 서버 안 저장, 로그인 없음"까지만 확정한다.
