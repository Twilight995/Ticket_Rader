# Suno 참고 디자인 검토

검토일: 2026-11-01 (한국 시간)

## 검토 범위와 한계

- Mobbin Suno iOS UI Elements 목록(표시 수 131개)을 브라우저에서 탐색했다. 초반 18개는 개별 확대, 이후는 사용량을 줄여 달라는 요청에 따라 목록 묶음 중심으로 확인했다.
- 목록 끝까지 이동했으나 일부 캡처는 이미지 로딩 지연이나 화면 경계 때문에 부분만 보였다. 따라서 **131개 모두를 빠짐없이 개별 정밀 검수했다는 의미는 아니다.**
- 비교에 필요한 만들기·버튼·카드 세부는 기존 `docs/reference/suno/`의 실제 캡처도 보조 자료로 직접 확인했다. 기존 작성자의 관찰 문구를 그대로 검증된 사실로 취급하지 않았다.
- 현재 열려 있는 `ticket_rader_mock.pen`의 디자인 시스템(`hDu9y`)과 판매글 입력 네 상태(`y0cnJP`)를 MCP로 읽고 렌더링했다. 색·치수는 현재 pen 값이고, Suno의 정확한 원본 토큰이나 글꼴은 알 수 없다.
- 디자인은 수정하지 않았다. 정적인 디자인 검토이며 실제 클릭 동작·키보드 대응·로딩 애니메이션 검증은 아니다.

## 판단

Suno의 핵심 부품은 상당히 잘 반영돼 있다. 특히 Simple 만들기 화면에서 가져온 큰 입력 카드, 점선 첨부 칩, 원형 도구, 휴지통과 질감 있는 주요 버튼의 조합은 근거가 분명하다. 다만 전체 표면은 원본보다 평평하고 제목은 더 무겁게 느껴진다. 부품을 다시 만드는 것보다 배경·타이포그래피와 상태 구분을 다듬는 편이 적절하다.

## 수정 우선순위

### 1. 오류 화면을 파일 오류와 연결 실패로 분리

현재 `COpUP`에는 6.8MB 이미지, 파일 제한 오류, 다른 이미지 올리기, 연결 실패, 다시 시도, 활성 주요 버튼이 함께 있다. 서로 다른 실패 원인이 한 장에 겹쳐 있어 행동 우선순위가 모호하다.

- 파일 오류: 파일 근처에 오류와 교체 행동을 두고, 유효한 텍스트만으로 진행할 수 있는지 명세에 맞춰 주요 버튼 상태를 정한다.
- 연결 실패: 입력은 유지하고 재시도 행동을 하나로 정리한다. 주요 버튼을 '다시 확인하기'로 바꾸거나 별도 재시도 버튼을 쓰되, 같은 일을 하는 두 버튼을 경쟁시키지 않는다.
- 현재 입력 카드 높이는 정상 512px에서 오류 376px로 136px 줄어든다. 전체 안내를 별도 상태로 나누면 도움말과 첨부 영역의 큰 이동도 줄일 수 있다.

이는 Suno 유사도보다 실제 사용성에 관한 우선 수정 항목이다.

### 2. 배경과 카드에 절제된 색 깊이 추가

현재 화면은 `#0B0B0D`, 입력 카드는 `#1C1C1F` 단색이다. 확인한 Suno 만들기 화면은 어두운 바탕에 갈색·자주색 기운과 미세한 질감이 있고, 카드가 배경과 자연스럽게 이어진다.

선택한 입력 화면에만 매우 약한 따뜻한 색 번짐과 반투명 표면을 시험하는 것을 권한다. 모든 화면을 화려한 그라데이션으로 채울 필요는 없다. 정확한 투명도·색 값은 원본에서 측정하지 않았으므로 새 제안값과 원본값을 구분해야 한다.

### 3. 세리프 제목의 무게 조정

현재 제목은 Noto Serif KR 28px/600, 중앙 정렬이다. Suno의 'When’s your birthday?'나 'Do More With Suno'는 상대적으로 가늘고 획 대비가 커 보인다. 400 또는 500 굵기를 비교 시안으로 확인할 가치가 있다.

단, Suno Simple 만들기 자체에는 현재 티켓레이더처럼 큰 세리프 설명 영역이 없다. 현재 화면은 온보딩 제목과 만들기 입력부를 조합한 디자인이다. 첫 방문 안내를 유지하는 선택은 가능하지만, Simple을 그대로 재현한 것으로 설명하면 부정확하다.

### 4. 입력 카드 높이는 오류로 단정하지 말고 두 안 비교

현재 정상 상태에서 카드 높이는 512px이며, 본문 72px와 첨부 60px 아래에 여유 공간이 크다. 긴 판매글을 입력하는 목적이라면 충분히 타당하다. Suno도 큰 입력 면을 사용한다.

- 현행안: 긴 글 입력과 안정된 하단 주요 버튼 위치에 유리.
- 대안: 안내 영역 또는 카드 높이를 줄여 처음 보이는 화면의 밀도를 높임.

Suno와 비슷해 보이게 하려고 무조건 줄이지 말고, 짧은 글·긴 글·키보드 표시 상태에서 선택해야 한다.

### 5. 로딩 중 행동 가능 여부 명시

현재는 주요 버튼이 '읽는 중…'으로 바뀌지만 휴지통과 첨부 도구는 기존 모양으로 남아 있다. 정적 화면만으로 실제 활성 여부를 확정할 수 없다.

읽는 동안 수정·삭제를 막는다면 비활성 표현을 일관되게 적용한다. 허용한다면 진행 중 요청을 취소하는지 정한다. Suno의 진행 알약을 가져오는 것도 가능하지만, 단일 작업 화면에서는 현재의 하단 상태 표시만으로도 충분할 수 있다.

### 6. 토큰 문서와 pen 값 동기화

| 항목 | 현재 pen | design-tokens.md | 필요한 정리 |
|---|---|---|---|
| `tr-h-cta` | 변수 56, 실제 주요 버튼 54 | 치수 표 54, 부품 표 50 | 사용할 기준값 하나로 통일 |
| 휴지통 | 실제 54 | 부품 표 46 | 부품 표 갱신 |
| CTA 간격 | 실제 12 | 부품 표 10 | 부품 표 갱신 |
| 카드 모서리 | 공통 토큰 16, 입력 카드 20 | 예외 표기 있음 | 의도한 예외로 유지 가능 |
| 작은 글자 | 12px 토큰 존재 | '12px는 쓰지 않는다'와 12px 사용처가 공존 | 허용 범위를 명확히 정리 |

숫자가 다르다고 전부 시각적 결함은 아니다. 그러나 개발자가 문서를 기준으로 구현하면 현재 디자인과 달라질 수 있으므로 정리가 필요하다.

## 최종 권고

현재 디자인을 유지하고, **오류 상태 분리 → 문서·토큰 정합성 → 배경 깊이와 제목 무게** 순서로 수정하는 것을 권한다. Suno의 하단 음악 탐색바·피드·계정 기능을 가져올 필요는 없다. 판매글 확인이라는 목적에 맞는 부품만 유지하는 편이 적절하다.
